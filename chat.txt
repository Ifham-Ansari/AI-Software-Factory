The development rule I recommend

For every phase, we'll follow exactly this cycle:

DESIGN
  ↓
IMPLEMENT
  ↓
UNIT TEST
  ↓
INTEGRATION TEST
  ↓
FAILURE TEST
  ↓
FIX
  ↓
END-TO-END TEST
  ↓
DOCUMENT
  ↓
PHASE COMPLETE ✓
  ↓
NEXT PHASE

And importantly, we don't sneak features from later phases into earlier ones.

For example, Phase 1 should not touch deployment. Phase 1's only responsibility is:

Take a natural-language project request → identify requirements → collect missing configuration → validate it → produce a structured Project Specification.

Once that works reliably, we move to Phase 2 and introduce the hierarchical LangGraph architecture.

This gives us a clean progression from single intelligent intake agent → hierarchical multi-agent system → autonomous software generation → autonomous deployment → supervised production AI factory.
